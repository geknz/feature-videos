# Feature Videos

Сделай короткую презентацию одной фичи: контекст → действие → реакция UI → результат → возврат. Для правок существующего видео продолжай с нужного этапа и сохраняй удачные материалы.

Источник: сайт, репозиторий приложения или Figma-дизайны, плюс сценарий. Используй доступные инструменты для чтения источника; при отсутствии компонентов подготовь отдельный съёмочный UI по доступному дизайну.

## Подготовка

1. Прочитай [гайд серии](references/GUIDELINE.md) и [motion tokens](assets/motion-tokens.json) до сценария и реализации.
2. Из запроса и проекта определи продукт, одну фичу, стартовое состояние, действие и подтверждённый результат. Если фича неизвестна, уточни только её. Не запрашивай повторно уже заданные параметры.
3. Скопируй [шаблон брифа](references/BRIEF_TEMPLATE.md) в каталог ролика и заполни brief/shotlist. Затем переходи к реализации; отдельное согласование плана не требуется, если пользователь его не запросил.
4. Для мобильного ролика прочитай [спецификацию рамки](references/DEVICE_FRAME.md). Для desktop используй фронтальное окно.

Текущий запрос пользователя имеет приоритет над настройками серии. Явно запрошенные отклонения занеси в brief; не требуй отдельного разрешения на них. Эти настройки относятся к роликам этой серии, а не ко всему дизайну продукта.

## Реализация

- База: 10 секунд (обычно 8–12), 1080×1350, 60 fps, без звука, внешних титров и курсора. 9:16 — отдельная композиция и экспорт, когда запрошена.
- Сохрани UI, язык, шрифты, ассеты и смысл состояний продукта. Не переносить Netflix-брендинг на другой продукт.
- Съёмочный слой держи отдельно от приложения. Сохраняй собственную физику Rive, частиц и нативных анимаций; изменения для съёмки отмечай в shotlist.
- Камера и добавленные переходы — linear. Используй [motion.mjs](assets/motion.mjs): камера 600 ms, панель 500 ms, press 80+120 ms, пауза на результате минимум 1 s после окончания реакции. Полные параметры — в tokens и гайде.
- Для мобильного видео скопируй [CSS](assets/device-frame.css), [HTML](assets/device-frame.html) и [JSON](assets/device-frame.json) рамки в каталог ролика. Размер 390×844, radius 48, island 112×30. Это кастомный мокап, не конкретная модель iPhone.
- Сверь геометрию с [референсом](assets/netflix-device-reference.jpg), статус-бар — с актуальными HTML/CSS/JSON и [превью](assets/status-bar-preview.png). Не дублируй статус-бар и home indicator. Цель крупного плана выбирай под текущую фичу.
- Все временные параметры helpers — секунды; значения `*Ms` в JSON перед использованием переводи в секунды. При копировании motion tokens сохраняй рядом device-frame.json, на который ссылается `deviceSpec`.
- Используй один timeline, загруженные локальные ассеты и фиксированные данные. Реальные результаты показывай после подтверждения состояния; поведение прототипа не выдавай за работающую интеграцию.
- Loop не должен заметно откатывать баланс, награду или прогресс. Если честный loop невозможен, заканчивай на результате.

## Скорость итераций

Приоритет — быстро показать изменения. Для новых роликов используй готовый [starter](assets/starter/) через `scripts/new-project.py`; команды и контракт сцен — в [FAST_WORKFLOW.md](references/FAST_WORKFLOW.md). В существующем проекте сохраняй рабочий UI и переноси только нужные части пайплайна.

Основной цикл: изменить сцену → проверить её ключевые кадры и соседние стыки → собрать быстрый draft из изменённых сцен и кеша. Неизменённые сцены не рендерить и не проверять заново без причины. Общие стили, камера, данные или ассеты инвалидируют всех зависимых потребителей. Используй исходные компоненты продукта, если доступны.

Черновик по умолчанию: половинное разрешение, 30 fps, DPR1. Один final 60 fps / DPR2 — после завершения правок или по запросу готового файла, а не на каждой итерации. Не требуй дополнительного согласования финального экспорта, если он уже входит в запрос. Рабочие файлы и кеш сохраняй в проекте, не в установленном скилле.

## Экспорт и проверка

1. Для финальной доставки экспортируй MP4/H.264/yuv420p, 60 fps, faststart, без аудиодорожки по умолчанию. По возможности рендерь 2× и уменьшай Lanczos. Промежуточные итерации оставляй в draft-профиле.
2. Просмотри конечный MP4 на нормальной скорости и ключевые кадры: клик, вход/выход панели, результат и стык. Проверь читаемость, отсутствие обрезаний, двойного press, ошибок и скачков камеры.
3. Проверь ffprobe: размер, fps, длительность и аудио; ffmpeg — декодирование без ошибок. Для loop сравни первый и последний кадр. Каждую композицию проверяй отдельно.
4. Верни MP4, контактный лист, исходники, точную команду повторного рендера и краткий QA. Укажи непроверенное, если проверку выполнить не удалось; не называй такой результат полностью проверенным.

Создание видео не включает публикацию или деплой.

## Flask

Когда загрузка входит в задачу, прикладывай исходники и notes к той же версии. После успешной загрузки верни ссылку и заверши задачу. Не вызывай `wait_for_feedback` и не держи задачу открытой ради ожидания, если пользователь отдельно этого не попросил. Новый фидбек читать по запросу пользователя. Эта явная пользовательская настройка отменяет стандартное ожидание Flask в данном workflow.
