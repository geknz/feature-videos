# Быстрые итерации

Создай проект один раз:

```sh
python3 ~/feature-videos/scripts/new-project.py /absolute/path/to/new-film
cd /absolute/path/to/new-film
npm install
npm run dev
```

Нужны Node, Chrome, FFmpeg/ffprobe. Playwright закреплён в package.json; сохраняй полученный package-lock.json и добавь его в `film.dependencies`. Пример в шаблоне — проверка инфраструктуры, не готовый дизайн продукта. Заменить его реальными компонентами. Для React/Vite сохрани контракт capture API и подключи соответствующий dev server вместо встроенного статического сервера.

## Цикл работы

1. `npm run plan` — показывает, какие сцены устарели для черновика.
2. `npm run check` — только ключевые кадры изменённых сцен. Открыть PNG из `.cache/.../check-*.png`, пути в `qa/check.json`. Автоматическая проверка не заменяет визуальную.
3. `npm run draft` — изменённые сцены, 540×676 (чётная высота для H.264) / 30 fps / DPR1; результат `out/draft.mp4`. Остальные сцены берутся из кеша; сборка без перекодирования. Это основной результат каждой итерации, явно обозначать его как черновик.
4. Когда содержание стабильно, `npm run final` — один итоговый экспорт 1080×1350 / 60 fps / DPR2. При последующих правках повторно рендерятся только изменённые финальные блоки. Полностью неизменённая сборка переиспользуется.

Не запускать full-quality автоматически после каждой правки. Если пользователь просит готовый финальный файл, выполнить final после проверки изменений без дополнительного согласования. Быстрый draft допустим для промежуточного показа во Flask; каждый upload включает актуальные исходники и notes.

## Сцены и кеш

`film.json`: размеры, профили, упорядоченный массив `scenes`. Каждая сцена имеет уникальный id, duration, entry, checks (локальное время в секундах), dependencies (файлы/каталоги). Длительность кратна одному кадру обоих профилей.

- `src/scenes/<id>/` — только файлы этой сцены; свои ассеты также здесь.
- Остальные файлы `src/`, `scripts/`, index.html и package.json — общие, изменение инвалидирует все сцены.
- Ассеты вне src, lockfile, внешние компоненты монорепозитория и их транзитивные зависимости включить в `film.dependencies` (все сцены) или `scene.dependencies`. Каталоги хешируются рекурсивно. Не включать node_modules, out, qa, .cache. Внешние сетевые ассеты сначала сохранить локально.
- При сомнениях зависимость считать общей. Нельзя экономить время ценой устаревших кадров.
- Порядок сцен меняет только сборку. Изменение длительности затрагивает саму сцену. При изменении входного состояния следующей сцены обновить её данные/зависимости.
- Каждая сцена вычисляет полный UI и камеру из **локального времени**, без накопления состояния от предыдущего вызова. `mount(root)` и `seek(t, context)` должны работать с произвольным порядком seek.
- Переход принадлежит одной сцене. Её первая/последняя поза должны совпадать с соседями. Если переход использует соседний UI, добавить его файлы в dependencies; тогда правка соседа инвалидирует переход.
- Случайность фиксировать seed; Date.now, live API, CSS clock и сеть не должны менять кадры.

Capture API: `window.seek(sceneId, localSeconds)` применяет кадр; `window.prepare(sceneId, checkpoints)` заранее загружает ассеты и шрифты; `window.ready` сигнализирует готовность. Не декодировать все изображения на каждом кадре. Ассеты, появляющиеся между checkpoints, включить в preload или добавить checkpoint.

Кеш раздельный для draft/final. SHA256 проверяет целостность готовых клипов; interrupted render не считается готовым. Рендер выполняется последовательно, чтобы не перегружать машину; сначала измерять, затем добавлять параллелизм. Не запускать два render процесса одновременно в одном каталоге проекта.

## Проверка и доставка

Во время итераций смотреть изменённые сцены, их стыки с соседями и новый общий draft. Не пересматривать все неизменённые кадры. Перед доставкой final один раз посмотреть конечный MP4 целиком, проверить стыки и loop; скрипт проверяет декодирование новых клипов, размеры, число кадров, отсутствие аудио и длительность сборки. Отдельный профиль/формат — отдельный кеш и QA.

Для source.zip включить film.json, src, scripts, index.html, package.json, lockfile, brief и нужные внешние исходники либо явно описать зависимость от репозитория. Исключить node_modules, .cache, out, qa и видео. Общий контактный лист создавать из уже полученных кадров, не новым рендером.

После успешной загрузки во Flask вернуть ссылку и завершить задачу. **Не вызывать wait_for_feedback и не ждать 10 минут**, если пользователь отдельно не попросил ждать или следить. Проверять новый фидбек по следующему запросу пользователя. Это явная настройка пользователя для этого процесса, она имеет приоритет над стандартным циклом ожидания Flask. Не менять установленный плагин Flask и не отключать ожидание в других задачах.
