# Feature videos — guideline v1.1

Стандарт серии коротких видео о фичах разных продуктов. Зафиксирован 29 октября 2026.

## Решение пользователя

Последнее уточнение — «линейную». В этом гайде это означает **постоянную скорость постановочной камеры и добавленных для видео переходов**, без spring, overshoot и bounce. Это новое правило серии, а не описание уже отрендеренного balanced.

`netflix-streaks-loop-balanced.mp4` — референс композиции и рассказа. Его easing не копировать: исходник смешивает 35% damped response и 65% cubic-bezier, у toast — 30/70. Ни balanced, ни eased не являются linear.

Встроенные анимации продукта (Rive, частицы, физика жестов, прогресс реального процесса) сохраняют свою временную логику. Не нужно превращать физику конфетти в линейное перемещение. Если адаптируем только для съёмки вход панели/уведомления, используем linear и явно записываем отличие в shotlist.

## 1. Что объединяет серию

**Один ролик = одна фича, один короткий сценарий, один понятный результат.**

Последовательность: контекст → действие → реакция интерфейса → результат → возврат.
Демонстрация должна читаться без звука и поясняющего текста вокруг ролика.

Постоянны:

- Фронтальная подача устройства/интерфейса без вращения в 3D.
- Одинаковые пропорции общего и крупного плана в рамках одного формата.
- Одинаковая линейная камера, короткое подтверждение нажатия, пауза на результате.
- Один главный объект внимания в каждый момент.
- Тихий фон, чистый экспорт, 60 fps, бесшовный loop, когда он возможен по сценарию.
- По умолчанию без вступительной заставки, внешних титров, курсора, музыки и звуков.

Меняются вместе с продуктом:

- UI, шрифт, цвета, иллюстрации, реальные состояния и действия.
- Мобильная оболочка фиксирована: `netflix-movie-device-v1` из [DEVICE_FRAME.md](DEVICE_FRAME.md) и [`device-frame.css`](../assets/device-frame.css). Для desktop — фронтальное окно без искусственного переноса продукта в телефон.
- Акцент фона: один приглушённый цвет из продукта. Композиция фона и контраст сохраняются.
- Специальный эффект только по смыслу фичи. N-конфетти, Netflix-красный и огонёк не являются обязательными элементами серии.

## 2. Сценарий и ритм

Базовая длина — **10 секунд**. Допустимо 8–12 секунд, если сценарий выигрывает в понятности. Это рекомендуемые параметры нового стандарта, а не замеры всех прошлых версий.

| Фаза | Задача | Ориентир |
|---|---|---|
| Контекст | Узнать продукт и стартовое состояние | 0.5–0.8 s |
| Приближение | Показать область следующего действия | 0.6 s |
| Действие и реакция | Нажатие и немедленная обратная связь | 0.2 s на нажатие + время ответа |
| Состояние фичи | Понять, что открылось/изменилось | 1.0–2.0 s |
| Второе действие, если нужно | Завершить тот же сценарий | до одного дополнительного действия |
| Результат | Прочитать подтверждение и понять пользу | минимум 1.0 s, обычно 1.2–1.5 s |
| Возврат | Вернуться к общей композиции | 0.6 s + 0.5–0.8 s покоя |

Не ужимать существующие анимации ради хронометража. Сначала сокращать пустое ожидание; затем убрать лишнее действие; только затем увеличить длительность.
Пауза на результате начинается **после завершения реакции**, а не до клика. Во время неё Rive и другие живые элементы продолжают работать.

## 3. Композиция

- Master: 1080×1350, 4:5. Stories: 1080×1920, 9:16 — отдельная композиция и рендер.
- **Точная рамка Netflix обязательна для мобильной серии:** viewport 390×844, radius 48 px, Dynamic Island 112×30 px. Полная спецификация — [DEVICE_FRAME.md](DEVICE_FRAME.md); готовые файлы — [`device-frame.css`](../assets/device-frame.css), [`device-frame.html`](../assets/device-frame.html), [`device-frame.json`](../assets/device-frame.json).
- Общий план 4:5: left 345, top 253, scale 1.28. Общий план 9:16: left 345, top 538, scale 1.7. Все размеры до масштабирования в CSS px; параметры не подбирать на глаз.
- Камера смотрит прямо. Без перспективы, боковых кнопок, второй рамки и дополнительных бликов. Это кастомный CSS-мокап, не конкретная подтверждённая модель iPhone.
- Крупные планы Netflix: absolute scale 2.35–2.4. Это ~1.84–1.88× от общего в 4:5, но ~1.38–1.41× в 9:16. Цель камеры адаптируется под фичу, рамка сохраняется. Ключевые подписи, кнопка и подтверждение должны оставаться в кадре.
- До 2 зон фокуса: вход в фичу и завершение сценария. Больше — повод разделить видео.
- Ключевое действие располагать в центральных 70–80% кадра; учитывать элементы платформы отдельно для финального placement.
- Фон не двигается. Нейтральная тёмная база и мягкий приглушённый акцент внизу. Для светлого UI сохранить достаточное разделение с фоном.
- Не зумить резко на мелкую метрику, которую зритель не успеет прочитать. Лучше изменить кадрирование.

## 4. Motion tokens

Машиночитаемый источник параметров — [`motion-tokens.json`](../assets/motion-tokens.json). Эталон линейной интерполяции — [`motion.mjs`](../assets/motion.mjs).

| Элемент | Стандарт |
|---|---|
| Камера push-in / pull-out | 600 ms, linear |
| Панель/drawer в постановочном слое | 500 ms, linear |
| Toast в постановочном слое | 350 ms, linear; перемещение 24 px + opacity 0→1 |
| Нажатие | scale 1→0.98 за 80 ms, затем 0.98→1 за 120 ms; оба отрезка linear |
| Подсветка нажатия | белый слой 0→5%→0, синхронно со scale |
| Замена статуса, иконки | 200 ms, linear; сохранить смысл перехода продукта |
| Пауза после завершения | 1200 ms по умолчанию |
| Дополнительный motion blur | выключен |
| Overshoot / spring / bounce / shake | выключены в постановочном слое |

Линейная камера имеет резкую смену скорости на границе движения и покоя: это ожидаемое свойство linear. Не обещать одновременно constant speed и мягкий разгон/торможение. Смягчать восприятие выбором короткого перемещения, длительности и спокойных пауз, не скрытой подменой easing.

Вычислять один progress `p = clamp((t-start)/duration, 0, 1)`. Позицию и scale интерполировать по этому progress напрямую. Не перемножать отдельно меняющиеся focusY и scale: итоговая траектория смещения станет нелинейной. Пример — `cameraPose()` в [`motion.mjs`](../assets/motion.mjs); CSS transform: `translate3d(x, y, 0) scale(scale)` при постоянном transform-origin.

Приближение заканчивается до клика, целевой элемент удерживается хотя бы ~150 ms. Открытие панели может идти одновременно с отъездом камеры, если они раскрывают одно действие. Не совмещать движение камеры, скролл и появление нескольких независимых объектов.

Нажатие обозначается изменением самого элемента. Не добавлять курсор/кружок касания поверх этого без необходимости; избегать двойного press от CSS и режиссёрского слоя.

## 5. Честность сценария

- Исходный UI и .riv не изменять ради монтажа. Съёмочные настройки — в отдельном прототипе/слое.
- Демо-событие может имитировать реальное действие, но результат должен соответствовать правилам фичи.
- Не показывать награду, оплату или сохранение как успешные до подтверждения соответствующего состояния.
- Для result hold допустимо продлить автоматическое закрытие в съёмочной копии; зафиксировать это в shotlist. Не замораживать общий animation clock.
- В loop возвращать видимую композицию, а не откатывать на глазах баланс, награду или прогресс. Если честный loop невозможен — закончить на результате и использовать чистый монтажный стык.

## 6. Текст и звук

- Базовый формат — silent UI demo. В первом Netflix-ролике нет аудиодорожки; сохранить этот принцип для второго.
- Продукт использует собственный шрифт и язык. Не заменять их общей «шрифтовой системой серии».
- Внешние объясняющие титры по умолчанию отсутствуют. Название фичи — в подписи публикации/обложке, если нужно.
- Если будущий сценарий требует текста, сначала согласовать отдельный единый шаблон титров для серии; не добавлять его только в один ролик случайным образом.

## 7. Экспорт и QA

Эти параметры относятся к финальной доставке. Для быстрых итераций применяй [FAST_WORKFLOW.md](FAST_WORKFLOW.md): draft, кеш сцен и проверка изменений; полный финальный экспорт только после завершения правок.

- MP4 / H.264 / yuv420p / 60 fps / без аудиодорожки / faststart. CRF 17–18 как стартовый пресет.
- По возможности рендерить 2× и уменьшать Lanczos. Не повышать разрешение уже готового размытого ролика.
- Локальные ассеты и шрифты загружены до старта записи. Фиксированные данные, время и сценарий.
- Один timeline управляет камерой, событиями и записью. Прогресс рассчитывается от времени, не от количества прошедших браузерных кадров.
- Закрепить версии библиотек. Seed для случайных частиц — если сравниваются разные монтажные версии; иначе отметить, что распределение частиц может меняться.
- Смотреть финальный mp4 на нормальной скорости и покадрово в точках клика, входа/выхода панели и стыка.
- Проверить: нет ошибок, загрузчиков и курсора; текст читается; press один; результат удержан; частицы не закрывают главное; нет случайных скачков позиции или изменения scale между фазами.
- Сравнить первый и последний кадр для loop. Проверить ffprobe: размер, fps, длительность, аудио.
- Просмотреть финальные 4:5 и 9:16 отдельно. Не считать вертикальную версию готовой после простого кропа.

## Исторический референс

Netflix balanced — референс композиции, не linear motion. Старые ролики не входят в пакет и не требуются для работы. Используй включённый референс рамки и актуальные CSS/HTML/JSON; параметры нового ролика проверяй заново.
